# AI 视频客服 Demo · 云端实测使用手册

**版本**：v1.0 实测版
**日期**：2026-09-29
**测试环境**：仙宫云 GPU 实例（RTX 4090D / 24GB）
**结论先说**：文字客服链路（客户 ↔ AI ↔ 人工坐席）在云端三角色全部跑通并截图取证；数字人（LiveTalking + Wav2LiP）GPU 推理已跑通，但**浏览器画面受仙宫云端口代理限制无法直连**，改用服务器环回抓帧取证。

---

## 1. 系统构成

| 组件 | 作用 | 端口 | 实测状态 |
|------|------|------|---------|
| LiveKit Server | 房间/信令/媒体 SFU | 7880(WS) / 7881(WHIP-WHEP) | ✓ `--dev` 模式运行 |
| LiveKit Agents worker | AI 客服进程，注册 RPC 方法 `ask` | 8081 | ✓ 已注册 |
| Ollama + qwen2.5:3b | 大模型推理 | 11434 | ✓ GPU 推理 |
| Token+Web 服务 | 发 token、托管页面、创建 dispatch | 3210 | ✓ |
| LiveTalking | 数字人唇形渲染（Wav2LiP） | 8010 | ✓ GPU 推理，画面见 §5 |

**角色模型**：同一个房间 `cs-demo` 里可有多个身份 —— `customer`（客户）、`human-seat`（人工坐席）、`agent-AJ_xxx`（AI 客服，由 worker 自动派生）。页面地址加 `?name=xxx` 即以该身份入房。

## 2. 云端访问方式（关键前提）

仙宫云的端口代理规则：**容器内任意端口 P，公网地址为**

```
https://{实例ID}-{P}.container.x-gpu.com
```

本例实例 ID 记作 `<实例ID>`，所以：

| 用途 | 公网地址 |
|------|---------|
| 客服页面 | `https://<实例ID>-3210.container.x-gpu.com/` |
| LiveTalking 控制台 | `https://<实例ID>-8010.container.x-gpu.com/admin.html` |
| LiveKit 信令 | `wss://<实例ID>-7880.container.x-gpu.com` |

**重要限制**：该代理只提供 HTTPS / WSS（TCP 通道），**不转发 UDP**。WebRTC 的媒体面走 UDP，因此浏览器直连数字人时信令能握手、ICE 卡在 `connecting`。服务端代码已按 Host 头自动推导公网 wss 地址：

```js
function publicLkUrl(req) {
  const host = req.headers.host || '';
  if (host.startsWith('localhost') || host.startsWith('127.')) return 'ws://localhost:7880';
  return 'wss://' + host.replace(/-\d+\./, '-7880.');
}
```

## 3. 部署步骤（可复跑）

```bash
# 1) LiveKit Server（二进制从 GitHub Releases 取，Docker Hub 不可用）
tar -xzf livekit-server.tar.gz && ./livekit-server --dev &

# 2) Ollama（GitHub release 二进制）+ 模型
tar -xzf ollama-linux-amd64.tgz && ./ollama serve &
./ollama pull qwen2.5:3b

# 3) Agents worker（Python 3.10 + 清华源）
pip install livekit-agents==1.8.3
export LIVEKIT_URL=ws://localhost:7880 LIVEKIT_API_KEY=devkey LIVEKIT_API_SECRET=secret
python -u agent.py start &

# 4) Web + Token 服务
cd web && npm install && node server.js &

# 5) LiveTalking 数字人（模型权重走 Google Drive，云端几秒完成，本地无法下载）
python -u app.py --transport webrtc --model wav2lip --avatar_id wav2lip256_avatar1 &
```

> 注意：`livekit-server --dev` 已隐含 `devkey/secret`，再传 `--keys devkey=secret` 会报 `needs to be exactly, key: secret` 格式错误。

- `AI客服: ...` —— RPC 同步返回值（`performRpc(method:'ask')`）

### 5.1 管理控制台

`https://...-8010.container.x-gpu.com/admin.html` 可见全局配置与活跃会话：模型 `wav2lip`、角色 `wav2lip256_avatar1`、TTS `edgetts`、传输 `webrtc`、端口 8010、batch 16、fps 25。

### 5.2 GPU 占用（nvidia-smi 实测）

```
NVIDIA GeForce RTX 4090 D   memory.used 2542 MiB / 24564 MiB
compute app: pid 803 (LiveTalking) 2532 MiB
```

### 5.3 画面取证：服务器环回抓帧

浏览器侧因 §2 的 UDP 限制拿不到画面，因此在**同一台服务器内**跑一个 aiortc 环回客户端：向 `127.0.0.1:8010/offer` 提交 SDP、从 `/api/admin/sessions` 取 sessionid、用 `/human` 驱动播报，再把收到的 RTP 帧落盘。

```bash
python -u lt_loopback.py     # 输出 /root/aics/frames/lt_*.jpg
```

实测结果：连接 `connected`，收到 `sendonly` 的音视频轨，连续取到 7 帧，帧间平均像素差 5.8–6.8（嘴部区域 2.8–3.3），证明是**实时渲染而非静止图**。

![数字人-GPU口型序列](evidence/04-数字人-GPU口型序列.jpg)

### 5.4 信令方向坑（复现时必看）

`/offer` 的 SDP 中客户端轨道必须是 **recvonly**。若写成 sendonly，服务端 `aiortc` 在 `setLocalDescription` 里做方向与运算时会抛 `ValueError: None is not in list`，HTTP 直接 500。

```js
pc.addTransceiver('video', { direction: 'recvonly' });
pc.addTransceiver('audio', { direction: 'recvonly' });
```

## 6. 转写广播踩过的两个坑（已修）

| 现象 | 根因 | 修法 |
|------|------|------|
| agent 发了 `[转写]`，Python 客户端收不到 | `send_text()` 默认 `topic=''`，SDK 日志 `ignoring text stream with topic '', no callback attached` | 显式传 topic |
| topic 用 `lk.chat` 后 Python 收到、浏览器仍收不到 | `lk.chat` 被 livekit-client 官方聊天协议（protobuf ChatMessage）占用，纯文本被静默丢弃 | 换自定义 topic `transcript` |
| 浏览器 handler 触发了但内容不显示 | web SDK `reader.readAll()` 返回 **string**，`new TextDecoder().decode(string)` 抛类型错 | 判类型后再解码 |

最终前端代码：

```js
room.registerTextStreamHandler('transcript', async (reader, participant) => {
  const raw = await reader.readAll();
  const txt = typeof raw === 'string' ? raw : new TextDecoder().decode(raw);
  const sender = participant ? String(participant.identity) : '';
  log(txt, sender === String(room.localParticipant.identity) ? 'sys' : 'bot');
});
```

另有一处健壮性修复：房间里可能残留多个历史 `agent-*` 参与者，RPC 打到僵尸实例会 `Connection timeout`。前端改为按 `joinedAt` 取**最新**的 agent：

```js
agents.sort((a, b) => (a.joinedAt?.getTime() || 0) - (b.joinedAt?.getTime() || 0));
agentIdentity = agents[agents.length - 1].identity;
```

## 7. 实测性能与已知限制

| 项 | 实测值 | 说明 |
|----|--------|------|
| AI 首答延迟 | 约 30s | Ollama 冷启动加载 3B 权重 |
| AI 后续问答 | 约 3s | 模型常驻显存 |
| LiveTalking 显存 | 2532 MiB | 4090D 单实例 |
| 浏览器直连数字人画面 | **不通** | 仙宫云代理不转发 UDP，WebRTC 媒体无法穿越 |
| 语音 ASR | **未启用** | LiveTalking 提示 `funasr not installed`，仅文字驱动播报 |
| 转写广播 | 已修复并验证 | 见 §6 |
| 僵尸 agent 参与者 | 存在 | 前端已按最新 joinedAt 选择；服务端可 `removeParticipant` 清理 |
| 计费 | ¥1.59/小时 | 余额 ¥19.38，用完须及时关机 |

**要在真实网络里跑通数字人画面**，需要以下任一条件（本次环境都不具备）：公网直连 UDP/TCP 端口的服务器、LiveKit Cloud / 自建 coturn 中继、或把数字人视频回灌进 LiveKit 房间由 SFU 分发。
