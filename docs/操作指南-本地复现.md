# AI 视频客服本地 Demo — 部署与操作指南（方案一：LiveKit Agents + LiveTalking）

实测日期：2026-09-28 ｜ 机器：Windows 10 (10.0.26200) ｜ 结论：**LiveKit 高并发基座已全链路跑通并浏览器截图验证；LiveTalking 数字人层因本机无 GPU + 模型需网盘手动下载而受阻（如实标注，见 §5）**

## 1. 已验证的架构（全部在本机运行）

```
浏览器 (livekit-client WebRTC)
   │ ws://localhost:7880
   ▼
LiveKit Server v1.13.7 (二进制, devkey/secret)      ← 媒体SFU层，可横向扩容
   │ AgentDispatch (agentName=default)
   ▼
LiveKit Agents v1.8.3 worker (agent.py, 多进程)      ← 对话引擎层
   │ RPC "ask"
   ▼
Ollama qwen2.5:3b (本地 LLM, http://localhost:11434)  ← 无任何云端API Key
```

验证结果（两轮真实问答，见 `evidence/01-demo-two-round-qa.png`）：
- 问："你们的支持服务时间是怎样的？周末有人工客服吗？" → AI客服正确应答（9.5s，含模型冷启动）
- 问："如果产品有质量问题，怎么申请换新？" → AI客服应答（售后换新/退款指引）
- 房间内成员：customer + 2 个 AI 客服 agent 实例（两次 dispatch 各起一个 job，证明 worker 池化接单机制）

## 3. 从零复跑（4 条命令）

```bash
# ① LiveKit 服务端（dev 模式自带 devkey/secret）
./bin/livekit-server.exe --dev --bind 127.0.0.1

# ② Agent worker（生产模式，显式 dispatch 接单）
LIVEKIT_URL=ws://localhost:7880 LIVEKIT_API_KEY=devkey LIVEKIT_API_SECRET=secret \
  ./venv/Scripts/python.exe agent.py start

# ③ token+页面服务（需先确保 Ollama 已运行且有 qwen2.5:3b）
cd web && node server.js

# ④ 浏览器打开 http://localhost:3210 → 点"开始服务" → 提问
```

依赖安装要点（本机网络实测）：
- Docker Hub 不可达 → 用 GitHub Releases 二进制；下载走 `api.github.com/repos/.../releases/assets/<id>` + `Accept: application/octet-stream` 比直连 CDN 稳
- pip 官方源频繁中断 → 用清华镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple --timeout 60`
- git clone GitHub 走不通（本地代理失效）→ 用 `api.github.com/repos/<o>/<r>/zipball/main` + curl

## 4. 高并发说明（本 Demo 已体现的机制）

1. **多进程 worker 池**：livekit-agents 默认起 3 个 job runner 子进程（本实测日志 `initializing job runner` ×3），每进程可承载多路并发会话；
2. **显式 dispatch 模式**：每路客服会话 = 一次 `createDispatch(room, 'default')`，服务端把 job 派给空闲 worker——浏览器页每点一次"开始服务"即验证了一条新并发会话的完整准入链路；
3. **水平扩容路径**：worker 与 SFU 均无状态可独立加机器；生产建议 K8s + HPA（按并发房间数扩），SFU 层单机即可支撑数千路媒体转发；
4. **本次未压测**（如实标注）：可证伪判据 = 在 GPU 服务器上以 `locust/k6` 并发触发 dispatch + 语音链路，测单 worker 进程并发会话上限与 P99 首响延迟。

## 5. LiveTalking 数字人层 — 受阻原因与 GPU 机部署指南

**本机受阻（两条硬条件均不满足）：**
- 无 NVIDIA GPU（`nvidia-smi` 不存在；官方要求 CUDA 12.8 + PyTorch 2.9.1）
- 口型模型权重不在 git 仓库内，需从 README 所列**网盘手动下载**：
  - `wav2lip256.pth` → 放 `LiveTalking/models/wav2lip.pth`
  - `wav2lip256_avatar1.tar.gz` → 解压整个文件夹放 `LiveTalking/data/avatars/`

**有 GPU 机器上的部署（预计 30 分钟）：**
```bash
conda create -n livetalking python=3.12 && conda activate livetalking
pip install torch==2.9.1 torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
# 下载模型（见 README §模型下载 网盘表格）后：
python app.py --transport webrtc --model wav2lip --avatar_id wav2lip256_avatar1
# 打开 http://localhost:8010 即可看到数字人视频窗口
```
与 LiveKit 的对接方式：把本 Demo 的 `agent.py` 中 Ollama 答案文本，经 LiveTalking 的 `/human/submit` HTTP 接口（或 tts 通道）推给数字人渲染，数字人视频以摄像头/虚拟设备或 `streamout` 拉流方式回灌 LiveKit 房间。

**并发提示（README 实测结论）**：不说话时并发取决于 CPU，同时说话并发取决于 GPU——数字人层是整个系统 GPU 成本瓶颈，与调研报告 §四 的"媒体与计算分离 + 按需生成帧"策略一致。
